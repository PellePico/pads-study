The two pairs people mix up: Bubble vs selection: bubble fixes the end with lots of small neighbour swaps. Selection fixes the front with one swap per round. Merge vs quick: merge splits without thinking (just the middle) and does the hard work afterwards when gluing. Quick does the hard work first (splitting around the pivot), so gluing afterwards is just +.

What Big-O means

Big-O says how the work grows when the list gets bigger. It ignores how fast your computer is.

The easy test: double the list and see what happens to the work. n is the length of the list.

Big-On = 8n = 16Double n →
O(1)11same work
O(log n)34just +1 step
O(n)8162× the work
O(n log n)2464a bit more than 2×
O(n²)642564× the work

Two rules for writing it down:

  • Drop fixed numbers. 3n steps is still O(n): double n and 3n still doubles (n = 8: 24 → 48).
  • Keep only the biggest part. n² + n is O(n²): at n = 100 that is 10,000 + 100, so the n part hardly matters.

The five you will meet

O(1)

“constant”

Same work, however long the list is.

n = 8 → 1 step
n = 1000 → 1 step
Where
Grab one item: items[0]. Also len(items).

O(log n)

“log n”: halving

Each step throws away half. log n = how many halvings until 1 is left.

n = 8 → 8, 4, 2, 1 → 3 steps
n = 16 → 4 steps
Where
Binary search in a sorted list. Guess 1–100 with “higher / lower”: about 7 guesses.

O(n)

“linear”

Look at every item once.

n = 8 → 8 steps
n = 16 → 16 steps
Where
One loop over the list. Linear search, sum, max.

O(n log n)

“n log n”: halving × n

Halve about log n times. Each level touches all n items.

n = 8 → 3 levels × 8 = 24 steps
Where
Merge sort. Quick sort with good pivots.

O(n²)

“quadratic”: loop in a loop

For each item, go through the list again.

n = 8 → 8 × 8 = 64 steps
Where
Bubble, selection and insertion sort. Comparing every pair.

The five sorts

Space = extra memory while sorting. Stable = equal items keep their order.

SortBestAverageWorstSpaceStable?Why, in one line
bubbleO(n)O(n²)O(n²)O(1)YesPass after pass over n items. Already sorted → 1 pass, no swaps, break.
selectionO(n²)O(n²)O(n²)O(1)NoAlways scans the whole rest for the smallest, even if sorted. The long swap can jump an item past an equal one.

mergeO(n log n)O(n log n)O(n log n)O(n)YesAlways log n levels × n items to glue. The new lists need n extra spots. <= keeps ties in order.
quickO(n log n)
O(n) if all equal		O(n log n)O(n²)O(n) avg
O(n²) worst		Yes (this version)Good pivot halves the list. Bad pivot (always the smallest or biggest) peels off 1 item per level: n levels × n work.
  • Selection is not stable: [2a, 2b, 1] → swap 2a with 1 → [1, 2b, 2a]. The two 2s flipped.
  • Quick, all equal: [4, 4, 4, 4] → everything lands in equal, less and greater are empty. One pass: O(n).
  • Quick, space: every level builds new less / equal / greater lists. Good pivots: about n + n/2 + n/4 + … ≈ 2n waiting at once, so O(n). Bad pivots: n + (n−1) + … so O(n²).
  • In-place quick sort (swaps inside one list, no new lists) needs only O(log n) extra on average, for the waiting calls. But it is usually not stable.
  • Our Python versions start with out = list(items), a copy of n items. The O(1) above is the extra space for the sorting itself: just a few variables like i, j, swapped.

Time vs space

Time = how many steps. Space = how much extra memory.

Merge buys speed with memory. Bubble saves memory but is slow.

A stopwatch benchmark (e.g. timeit) measures time only, not memory.
